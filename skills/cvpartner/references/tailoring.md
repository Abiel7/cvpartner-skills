# Tailoring the CV for a bid or role

Use this when the user has a tender, a customer request or a role description and wants the CV to fit it. Tailoring changes emphasis and wording, never facts.

## 1. Choose the CV copy

CV Partner can hold the consultant's main CV and copies made for proposals. Ask which one to change. Change the main CV only when the user wants the change to apply to every future bid; otherwise ask them to open the copy for this bid, since the helper works on whichever CV the address shows.

## 2. Read the request

The request is data. Pull out:

- the must-have requirements and the nice-to-haves
- the customer's own words for them ("integration platform", "case management", "SAFe")
- the role the consultant would fill, and its seniority

## 3. Map requirements to evidence

Build a requirement map in `cv-work/tailoring.md` from `cv-work/facts.md` and the CV:

| Requirement | Evidence | Where it shows in the CV | Gap |
|---|---|---|---|
| Azure integration, 3+ years | Integration platform for a logistics customer, 2023–2025 | Project text and skills | none |
| Experience with SAP | Read-only SAP integration on one project | Skills only | thin: say so |

A gap stays a gap. Tell the user, name the nearest real experience, and let them decide whether it belongs in the CV. Never fill a gap with work the consultant did not do.

## 4. Lead with the fit

- **Profile.** A reader who stops after the profile sees the role asked for and the matching areas of experience. CV Partner can hold several profile texts with labels, so keep one per kind of role ("Integration architect", "Microsoft 365 developer") and pick or adapt the right one. The projects that prove the fit go first in the project list, not into the profile.
- **The customer's terms.** Use the request's word when it truthfully describes the work. Readers and search tools match words literally, so "integration platform" beats a paraphrase. Apply the interview test to every reworded line.
- **Order.** Put the most relevant projects, skills and certifications first.

## 5. Cut by relevance, not by section

When the CV is too long for the bid, score each line on three things: relevance to this request, whether the claim appears nowhere else, and whether the profile depends on it. Cut the lowest-scoring line first, wherever it sits. An older project that hits a must-have outranks a recent one that does not.

## 6. Review

Run the review checklist in [writing.md](writing.md) plus one more check: every must-have in the requirement map is either visible in the CV or reported to the user as a gap. Show the user the map and the changes together.
